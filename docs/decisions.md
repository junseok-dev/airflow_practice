# 의사결정 기록

프로젝트를 진행하면서 내린 주요 기술/설계 결정을 기록합니다.

## 2026-04-26

### 프로젝트 주제

결정: 교육생 역량 분석 대시보드

이유:

- React 프론트엔드 인턴 공고의 주요 업무가 교육생 역량 지표를 차트와 대시보드 형태로 구현하는 것이었다.
- 실습 결과물이 채용 공고와 직접 연결되어야 한다고 판단했다.

### 전체 구조

결정: React + FastAPI + Airflow 구조

이유:

- React는 공고의 핵심 기술이다.
- FastAPI는 React에서 호출할 REST API 서버를 빠르게 만들 수 있다.
- Airflow는 데이터 수집/정제/산출물 생성 흐름을 자동화하는 실습에 적합하다.

### 데이터셋

결정: OULAD 사용

이유:

- 직접 만든 mock 데이터는 전처리 연습에 한계가 있다.
- OULAD는 실제 학습 플랫폼 데이터이며, 교육생 정보, 평가 결과, 학습 활동 로그를 포함한다.
- 학생 성취도, 학습 참여도, 중도 이탈 위험도 같은 지표를 만들 수 있다.

### 원천 데이터 관리

결정: `data/raw/`는 Git에 올리지 않는다.

이유:

- `studentVle.csv`가 약 432.81 MB로 크다.
- 원천 데이터는 재다운로드 가능하고, Git 저장소에는 코드와 문서 중심으로 남기는 것이 좋다.

### 데이터 탐색 방식

결정: 첫 탐색은 pandas가 아니라 Python CSV 스트리밍 방식으로 처리한다.

이유:

- `studentVle.csv`가 10,655,280행으로 크다.
- 단순 행 수/컬럼/결측치 확인은 전체 DataFrame 로드 없이 처리할 수 있다.

### 문서화 방식

결정: README는 프로젝트 요약, `docs/`는 상세 작업 기록으로 분리한다.

이유:

- README가 너무 길어지면 전체 흐름 파악이 어려워진다.
- 진행 기록, 이슈, 의사결정, 전처리 결과는 별도 문서로 관리하는 편이 보고서처럼 읽기 좋다.

### 역량 점수 산식

결정: 첫 번째 mart 데이터에서는 평가 성취도, 학습 참여도, 학습 성실도를 조합해 종합 역량 점수를 만든다.

산식:

```text
종합 역량 점수 = 평가 성취도 45% + 학습 참여도 35% + 학습 성실도 20%
```

각 지표:

- 평가 성취도: 평가 평균 점수
- 학습 참여도: VLE 총 클릭 수를 95분위 기준으로 0-100 정규화
- 학습 성실도: 제출률 70%, 지연 제출률 30%

이유:

- OULAD에는 실제 출석 데이터가 없기 때문에 VLE 활동량을 학습 참여도의 대체 지표로 사용했다.
- 평가 점수만으로 역량을 판단하면 학습 과정의 참여도가 빠지므로 활동량과 제출 성실도를 함께 반영했다.
- 현재 산식은 첫 번째 대시보드 구현을 위한 기준이며, 화면 구현 후 조정할 수 있다.

### 위험도 기준

결정: 수강 철회, 낮은 평가 점수, 낮은 학습 활동량, 낮은 종합 역량 점수를 기준으로 위험도를 분류한다.

이유:

- 교육생 대시보드에서 관리가 필요한 교육생을 빠르게 찾는 기능이 필요하다.
- OULAD의 `Withdrawn` 결과는 중도 이탈 위험의 강한 신호로 볼 수 있다.
- 초기 기준은 보수적으로 잡고, 대시보드에서 분포를 확인한 뒤 조정한다.
